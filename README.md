# credential-scoring 重構教學版

這個專案是「臺北市消防局訓練中心證照積分統計系統」的教學重構版本。

原始 MVP 的特徵是：
- 單檔 `index.html`
- 前端計分邏輯
- 檔案轉 Base64 後送到 Google Apps Script
- GitHub Pages 靜態站部署

這不是壞事，而是很典型的實戰型 MVP：先把流程做出來，再逐步整理成可維護的結構。

---

## 這份教學版在做什麼？

目標不是換框架，也不是重寫成全端系統。

目標是：

**在不大改技術棧的前提下，把原本單檔 HTML 的責任切開，讓專案比較能活下去。**

---

## 六步驟重構路線

### Step 1：抽外觀
- 將原本寫在 `index.html` 裡的 CSS 抽出到 `css/styles.css`
- 目標：讓外觀不要跟頁面骨架與邏輯混在一起

### Step 2：抽規則資料
- 將 `AUDIT_UNITS` 與 `CONFIG` 抽出到 `js/config.js`
- 目標：讓單位清單與證照規則變成獨立資料層

### Step 3：抽畫面生成 / UI render
- 將 `initForm`、`updateCalc`、`prepareConfirmation`、`closeModal` 抽到 `js/ui.js`
- 目標：讓畫面生成與預覽 render 不再塞在主檔

### Step 4：抽計分邏輯
- 將有效性判斷、類別最高分採計、總分計算抽到 `js/scoring.js`
- 目標：讓 UI 不再兼任裁判與會計

### Step 5：抽驗證與提交流程
- 將送出前檢查抽到 `js/validation.js`
- 將 Base64、payload 組裝、GAS 送出抽到 `js/submit.js`
- 目標：讓「能不能送」與「怎麼送」從 UI 中分離

### Step 6：收尾整理
- 補上這份 README 與重構總結
- 目標：讓前面五步不只存在於 commit，也能被人理解與接手

## 目前檔案分工

### `index.html`
負責：
- 頁面骨架
- DOM 掛載點
- script / stylesheet 載入
- 少量尚未完全抽離的互動輔助函式

### `css/styles.css`
負責：
- 畫面樣式
- 動畫
- 響應式版面細節

### `js/config.js`
負責：
- 單位清單（`AUDIT_UNITS`）
- 證照與分數規則（`CONFIG`）

### `js/ui.js`
負責：
- 動態表單區塊 render
- 浮動分數板顯示更新
- 預覽 modal 清單生成

### `js/scoring.js`
負責：
- 證照有效性判斷
- 每類最佳分數判定
- 整體總分計算

### `js/validation.js`
負責：
- 基本欄位驗證
- 附件是否齊備的檢查
- 送出前驗證整合

### `js/submit.js`
負責：
- 檔案轉 Base64
- payload 組裝
- 提交到 GAS
- 成功頁切換

## 重構後的價值

這次重構沒有改變核心功能，但讓專案從：

- 外觀 / 規則 / UI / 計分 / 驗證 / 送出全塞在一個檔案

變成：

- 外觀有外觀房
- 規則有規則房
- UI 有 UI 房
- 計分有計分房
- 驗證有驗證房
- 送件有送件房

也就是說：

**不是重寫功能，而是把責任放回對的位置。**

---

## 下一步如果要做 v2，可以往哪走？

這份教學版先做到「可維護化」。

如果未來要往 v2 前進，下一輪可以考慮：

1. 讓送件結果可追蹤
   - submission id
   - 時間戳
   - 更清楚的送出回執

2. 補基本測試或 smoke test
   - 至少確保重構後主流程還活著

3. 重新思考檔案上傳策略
   - Base64 + GAS 對大檔與多檔會有壓力

4. 若需求擴大，再考慮更正式的前後端分離

## 總結

這個專案不是在比誰最潮，也不是在炫技。

它的核心是：

**把一個能跑的單檔 MVP，逐步整理成比較能維護、比較好教學、也比較不容易越改越痛苦的版本。**

這就是這份教學版存在的意義。
